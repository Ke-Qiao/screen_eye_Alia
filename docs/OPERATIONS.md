# Alia Eye · 操作、实现与历史验证记录

当前接入入口见[项目 README](../README.md)和[上位项目接入说明](INTEGRATION.md)。本文件保留交付整理前的操作细节与按日期记录的试验结果；命令均在项目根目录执行，较早记录中的“未验证”以之后的验证结果为准。

用于实体机器人眼睛模块的 2D 渲染系统。树莓派通过 Wi-Fi 发送位置指令，同一块 ESP32 分别控制两块 ST7789S TFT。每只眼在大虚拟画布上移动，经固定 Viewport 裁切后显示。

```text
电脑键盘 / .command 脚本 → SSH → 树莓派 → Wi-Fi TCP :4242 → ESP32
                                                           ↓
                       每眼 720×640 虚拟画布 → 240×320 Viewport → VSPI 屏1 / HSPI 屏2
```

图片驻留 ESP32 Flash，树莓派只发送控制指令，浏览器仅用于可选的校准界面。屏幕渲染不依赖浏览器、3D 球面或 PSRAM；物理透镜不参与软件计算，不做畸变校正或 LUT。

## 校准 WebUI

使用 `alia-eye-wifi-10` 固件以调整背光；界面也兼容 v7/v8/v9 的几何校准，但会禁用背光控件。先退出其他串口控制或自动演示窗口，再双击 `calibrate-eye.command`，或在项目目录执行：

```sh
.venv/bin/python pi/calibrate.py --port /dev/cu.usbserial-0001
```

浏览器打开 <http://127.0.0.1:8080/>，分别选择屏幕 1 / 2：

- 点击或拖动 240×320 预览设定眼睛中心，或直接填写 X（0…239）与 Y（0…319），所选实体屏幕实时跟随。画布方向键每次微调 1 px。
- 旋转角度范围 −180…+180°、精度 0.1°，正数顺时针。旋转围绕眼睛中心进行，超出屏幕部分正常裁切，空白区域填白。
- “哪一端是屏幕上方”选择排针端或排针对侧，对实际显示和上下左右一起补偿 180°；两屏分别设置。
- “背光亮度”支持滑块和数字输入，范围为整数 0–100%，实时调整所选屏幕的 PWM；0% 关闭背光，100% 常亮。单独调背光不改变眼睛位置、角度或另一屏，不触发 SPI 重画。百分比指 PWM 占空比，不是测得的光学亮度比例。
- 位置、角度、上下方向及回中按钮均实时更新，只改变所选屏幕并将该屏的相对眼动位置回中。更新时保留输入焦点与拖动，每屏只保留一个最新待发值；最多每 33 ms 发起一次校准请求，始终只有一个请求在途，设备响应较慢时直接跳到最新位置。这个请求频率不是实体屏幕帧率。
- 服务端将设置和两屏校准读回合并发送。v9/v10 的几何调整随后等待 `SYNC` 确认本轮绘制和 SPI 发送完成，网页才取最新位置发送下一次，减少旧位置提前排在上一帧后面的等待。v7/v8 保留参数接受确认。v10 另核对两屏亮度及 PWM 占空比；背光单独调整不等待图像刷新。连续调整复用已认证且检查过版本/尺寸的 TCP 连接，空闲 0.75 秒后在服务轮询中释放（通常不超过 1.25 秒）；新连接重新认证和检查。失败立即丢弃连接，不自动重放指令。另一屏仍逐次读回并检查回复编号。这些确认均不表示面板已完成光学扫描。
- 拖动不会写入存储。“保存到设备”仅在同步完成后可点，将两屏已同步的参数保存到 ESP32；重启后保留。通信失败会丢弃待发送队列并暂停自动发送，需先点“重新读取设备”核对当前状态，再继续调整，旧草稿不会自动重放。
- v10 的亮度同样仅在点击保存时落盘，使用 `eye_cal/backlight` 独立存储项，原有 44 字节几何配置和网络 NVS 格式不变。首次升级默认两屏 8%，之后启动加载已保存的亮度；保存失败时可能已有部分参数写入，应重新读取设备核对状态。
- “恢复本屏默认”应用中心 `(120,160)`、0°、屏幕 1 排针朝上/屏幕 2 排针朝下及 8% 背光；点保存后重启保留。

只替换眼睛外部背景，保留原来已接受的眼睛颜色。屏幕沿用校准界面加入前的初始化颜色模式，不再发送 `INVOFF`，界面不提供整屏反色开关。生成 RGB565 时，从图像边界向内查找外部背景及其灰色抗锯齿边缘，遇到深蓝轮廓停止（最暗通道 <8）。外部背景与灰色边缘一并替换为当前屏幕模式下显示白色的原生值 `0x0000`，再将最外轮廓内收 1 px、用 0.6 px 模糊的覆盖率向白底过渡，清理残留黑点和锯齿；画布露出的区域也填同一个背景值。距外部超过 3 px 的眼睛内部、瞳孔和封闭高光字节保持原样。浏览器 PNG 保留原图供定位，预览不能替代实体颜色验收。纹理尺寸仍为 150×228，背光默认 8%，可按屏调整。

校准参数存于独立 NVS 命名空间 `eye_cal`，仅点保存时写入；不改动 Wi-Fi/令牌的 `eye_net`。启动时校验结构、坐标、角度和方向，损坏/不支持的格式回到默认。兼容 v6 已保存的中心、角度和上下，忽略其废弃的反色设置。旧 XY/Y 命令继续作为相对于校准中心的眼动；原手动和演示脚本仍可使用。

使用无线控制时可在有令牌的电脑或树莓派运行：

```sh
.venv/bin/python pi/calibrate.py --host 192.168.10.133 --token-file /path/to/eye-control.token
```

服务仅监听 `127.0.0.1`，令牌留在服务端。若运行在树莓派，可通过 `ssh -L 8080:127.0.0.1:8080 ke-qiao@192.168.10.221` 转发后访问；需将前述地址替换为当前可达值。`--web-port` 可改端口。停止服务用 Ctrl+C，设备保持已应用设置。再次打开服务会读取设备保存或当前生效的值。

此次调校实际使用 Wi-Fi 模式，连续调整时短暂复用认证连接，空闲后释放。本机 USB 常驻服务曾在空闲后查询超时，无线也曾建连超时，原因尚未定位；遇到错误先重新读取设备状态，不自动重放设置。

## 已部署设备：直接使用

在 Finder 中双击 `manual-eye.command`。先退出正在运行的自动演示，ESP32 一次只接受一个控制连接。

| 按键 | 操作 |
|---|---|
| 1 / 2 / 0 | 选择屏幕 1 / 屏幕 2 / 双眼；编号对应接线图，不预设左右眼 |
| ↑ / W | 向上移动 10 px |
| ↓ / S | 向下移动 10 px |
| ← / A | 向左移动 10 px |
| → / D | 向右移动 10 px |
| 空格 | 当前选择的眼睛两轴居中 |
| R | 反转当前选择的眼睛的上下、左右按键方向，仅本次会话有效 |
| Q / Ctrl+C | 双眼居中并退出 |

方向键只控制当前选择；未选中的眼睛保持目标。切换选择不移动眼睛，双眼模式从各自位置相对移动，保留两眼的位置差；位置相同时使用一条同步目标命令。按住按键可通过键盘连发持续移动，终端显示两眼目标坐标和方向设置。启动时双眼先居中，空闲时每 5 秒发送查询保活；Ctrl+C 等待在途回复完成后再让双眼居中。结束后按回车关闭窗口。

`test-eye.command` 运行 120 秒双眼同步上下演示，幅度 12 px、周期 20 秒（竖装上下运动）；Ctrl+C 可提前结束并居中。

排查双屏显示时，双击 `test-dual-eye.command`，准备好后再选择：1 / 2 分别运行单屏上下测试（60 秒），3 运行双屏同步测试（3 分钟），4 打开方向键手动控制，5 让双屏居中并保持静止。当前竖装测试的运动幅度 12 px、周期 20 秒；单屏测试前先将双眼居中。Ctrl+C 停止运动并返回菜单，随后再次选择即可重播；手动模式按 Q 返回。留在菜单时可持续观察静止画面的颜色和横条。通信超时会中断本轮，不自动重试；报错区分 TCP 建连、认证、指令发送和等待回复。建连或认证超时表示本次连接还未发送眼动指令，指令发送或回复超时则不能确定是否执行。界面会明确提示尚未确认回中，可自行选 5 用新连接回中。

TCP 建连最多等待 6 秒，认证和一般指令回复最多等待 5 秒，为临时丢包后的 TCP 重传留出时间；发送数据仍限时 1 秒。正常收到回复即继续，不额外等待，也不在超时后自动重发运动。这只提高对短时网络波动的容忍度，不能修复持续断网；原有串口启动 `INFO` 握手仍允许短周期只读查询。

三个启动脚本保留当前设备的连接设置：

| 设置 | 当前值 |
|---|---|
| 树莓派 SSH | `ke-qiao@192.168.10.221` |
| 树莓派程序目录 | `/home/ke-qiao/Alia-eye` |
| ESP32 地址 | `192.168.10.133`，TCP 4242 |
| 树莓派令牌文件 | `/home/ke-qiao/Alia-eye/eye-control.token`，权限 0600 |

更换网络或设备时，修改三个 `.command` 文件中的 SSH 目标、ESP32 地址、远端程序及令牌路径。脚本复用 SSH 认证，不含密码或令牌内容。新环境使用 Python 虚拟环境时，也需将远端 `python3` 改为相应解释器的绝对路径。

## 硬件接线

本接线用于经典 ESP32，与 ESP32-S3/C3 不通用。

| TFT 信号 | 屏幕 1（VSPI） | 屏幕 2（HSPI） |
|---|---|---|
| SCLK / SCL | GPIO18 | GPIO14 |
| MOSI / SDA | GPIO23 | GPIO13 |
| MISO / SDO | 不连接 | 不连接 |
| CS | GPIO5 | GPIO22 |
| DC | GPIO27 | GPIO32 |
| RST / RES | 无此引脚，软件复位 | 无此引脚，软件复位 |
| BL | GPIO25，高电平点亮 | GPIO26，高电平点亮 |
| VCC | 3V3 | 3V3 |
| GND | 共地 | 共地 |

配置入口为 [`firmware/include/display_setup.h`](../firmware/include/display_setup.h)。[`st7789_panel.h`](../firmware/include/st7789_panel.h) 使用 Arduino-ESP32 自带的 `SPIClass`，分别控制 VSPI 与 HSPI，Mode 3、RGB565；命令与像素统一 10 MHz，顺序阻塞发送。基础初始化保留此前整帧路径（归属说明见 [`firmware/NOTICE`](../firmware/NOTICE)），随后按每屏校准设置 MADCTL，保留已验收的颜色模式。两块屏幕都使用 240×320 竖向寻址；`EYE1_FLIPPED=false` 对应屏幕 1 排针在上，`EYE2_FLIPPED=true` 对应屏幕 2 排针在下。屏幕 2 默认以 MADCTL 的 MX|MY 补偿 180° 安装；保存的每屏上下设置优先于编译默认值。两屏首帧完成后才开启背光。

启动和切换屏幕上下时发送完整 240×320 帧；移动和改变角度时，以旧、新图案外接矩形的并集作为一个刷新窗口，清除旧位置并绘制新位置。窗口包含旋转取样边缘余量并裁切到屏幕内，完全移出后不发送空窗口。每个窗口只设置一次地址，保持 CS 选通，逐块渲染并阻塞发送至多 8 行 RGB565，完成后才拉高 CS，再处理另一屏。0° 使用原 RGB565 行复制，旋转时保留原浮点取样，结果与 v8 逐像素一致。校准变化立即绘制，不等普通眼动的 33 ms 节拍；静止的屏幕不重写像素。启动标记仍为 `DISPLAY dual-blocking 10000000 3840 40`，当前版本为 `alia-eye-wifi-10`；启动另打印 `MOUNT portrait 0 1 150 228`。v10 仅增加背光控制，图像、颜色、渲染和 SPI 驱动沿用 v9。没有接入 TE 信号，因此缩小刷新窗口能减少传输延迟，但不能保证垂直同步。

此前试验的并行 DMA、整行局部刷新和独立 8 行事务版本均已撤回。后者在像素时钟降到 2 MHz 后仍出现屏幕 2 背光亮但无图，不能作为稳定版；故障快照和源码已保存在开发机 `.build/display-recovery-20261015/`。v8 从顺序整帧基线调整为一次一个矩形窗口，保留网络回复、连接状态和客户端半行回复修复；离线像素一致性不代表电气质量或长期颜色稳定性。用户暂不方便交换两块屏幕接线，尚未完成硬件隔离对照。

运动名义速度保留 40 px/s；结合已有 100 ms 时间步上限，每次刷新最多移动 4 px。实际速度受双屏发送耗时限制。测试菜单采用 ±12 px、20 秒周期；单眼各 60 秒、双眼 180 秒，便于观察颜色和停止后的画面。

当前接线没有 TE 同步输入，刷新仍可能在运动时撕裂。[ST7789S 数据手册第 127 页](https://newhavendisplay.com/content/app_notes/ST7789S.pdf) 说明 TE 输出可用于同步帧存储写入；接入前还需确认模块是否引出该信号，并核对刷新耗时与扫描时序。历史整帧回退曾复现屏幕 1 错色，根因尚未定位；v9 已通过颜色和跟随验收，v10 沿用其图像路径，长期稳定性与垂直同步仍未验证。

.venv/bin/pio run -d firmware -e esp32dev -t clean

```

烧录前确认端口与目标板；以下是当前 macOS 串口示例，其他机器需替换：

.venv/bin/pio run -d firmware -e esp32dev -t upload --upload-port /dev/cu.usbserial-0001
```

常规上传保留 NVS 网络配置。`esp32dev-wireless` 是禁用 TFT GPIO 的无线诊断构建，仅生成软件像素，不代表屏幕出图。

`esp32dev-usb-only` 用于无线射频隔离对照：不初始化 Wi-Fi，启动时必须确认驱动未初始化才打印 `RADIO disabled`；继续使用相同的双屏显示代码和 USB 控制协议。此构建拒绝 `CONFIG`，不读写已保存的配网信息，树莓派 TCP 和现有无线 `.command` 脚本暂不可用。用相同的构建/上传命令将 `-e` 换成该环境即可；观察完成后重新烧录 `esp32dev` 恢复无线控制，不需要重新配网。

`esp32dev-usb-softdrive` 是进一步的信号驱动对照，沿用 USB-only 的显示路径与 10 MHz 时钟，仅在初始化完成后将两屏 SCK/MOSI/CS/DC 设为 ESP-IDF 的 `GPIO_DRIVE_CAP_0`（弱驱动）。每个引脚打印 `SPI_DRIVE <pin> <before> <after>` 并检查读回；BL 保持原有设置。此设置只在该诊断构建生效，不能据此认定信号质量已改善。恢复 `esp32dev` 会恢复无线及原有引脚驱动设置。

## 新设备配网与树莓派部署

ESP32 需要 2.4 GHz Wi-Fi；树莓派可以使用同一路由器的 5 GHz，只要两台设备能够互访。配网在连接 ESP32 的电脑上通过 USB 串口完成，密码由隐藏提示输入：

```sh
mkdir -p .build/private
chmod 700 .build/private
.venv/bin/python tools/provision_wifi.py \
  --port /dev/cu.usbserial-0001 --ssid '你的 2.4 GHz Wi-Fi 名称' \
  --token-file .build/private/eye-control.token \
  --expect-mac aa:bb:cc:dd:ee:ff
```

将示例 MAC 和端口替换为目标设备实际值。工具先核对身份再保存配置；`OK CONFIG` 表示配置已保存，`NET <IP> 4242` 表示联网成功。已有有效令牌不会覆盖。也可用 `--wifi-file` 读取仅含 `ssid`、`password` 的 JSON，须为当前用户拥有、权限 0600 的普通文件，不应进入 Git。

在树莓派上准备客户端，目录须与启动脚本一致：

```sh
git clone https://github.com/Ke-Qiao/screen_eye_Alia.git ~/Alia-eye
cd ~/Alia-eye
python3 -m venv .venv
.venv/bin/pip install pyserial==3.5
```

树莓派仅需 Python、pySerial 和标准库 curses。将电脑生成的 `.build/private/eye-control.token` 通过 SSH/SCP 私密复制到树莓派工程目录的 `eye-control.token`，设为该用户拥有且权限 0600。文件内令牌须与设备 NVS 一致。

在树莓派工程目录执行，替换为配网工具报告的 ESP32 地址：

```sh
.venv/bin/python pi/eye_control.py \
  --host 192.168.10.133 --token-file eye-control.token --manual
.venv/bin/python pi/eye_control.py \
  --host 192.168.10.133 --token-file eye-control.token --screen 1 --xy 30 -20
.venv/bin/python pi/eye_control.py \
  --host 192.168.10.133 --token-file eye-control.token --screen 2 --xy -30 20
.venv/bin/python pi/eye_control.py \
  --host 192.168.10.133 --token-file eye-control.token \
  --demo --amplitude 60 --period 24 --seconds 120
```

USB 控制可用 `--port /dev/ttyUSB0` 替代 `--host` 和 `--token-file`。无线运行时 USB 线可以继续供电，应关闭串口监视器，避免打开串口引入复位干扰。DHCP 地址变化后更新脚本，或在路由器保留地址。

`--screen 1|2|both` 可用于 `--xy`、`--y` 和 `--demo`，省略时控制双眼。手动模式中它只决定启动时选择哪只眼，启动和退出仍会让双眼居中。新手动界面和单眼命令需要双屏固件；默认单次定位和旧演示仍可与旧固件通信。

## 渲染坐标与控制协议

大画布只是坐标空间，不分配整张画布。固定窗口左上角为 `(240,160)`，移动的是图案；每次更新旧、新图案覆盖区域的并集，清除旧位置。旋转的逆变换每帧计算一次，继续使用 8 行缓冲。

两屏竖向安装：`x` 增大向右，`y` 增大向下；上键发送负 y，右键发送正 x。屏幕 2 在显示控制器中补偿 180°，两眼使用相同逻辑坐标和正向纹理。`x` 范围 −285…+285，`y` 范围 −206…+206，每眼分别钳制；客户端通过 INFO/INFO2 自动读取范围。实际方向正负仍可用手动模式 R 按眼调整。

USB 为 115200 baud / 8N1；命令为 ASCII、换行结束。TCP 端口 4242，先发 `AUTH <64位小写hex令牌>`，收到 `OK AUTH` 后使用以下指令：

| 请求 | 响应 | 含义 |
|---|---|---|
| `EYES` | `EYES 2` | 双屏能力查询 |
| `INFO2` | `INFO2 240 320 -285 285 -206 206` | 屏幕尺寸与两轴范围 |
| `EYE 1 XY 30 -20` | `OKXY 1 30 -20` | 只设置屏幕 1 两轴目标；2 同理 |
| `EYE 2 Y -60` | `OK 2 -60` | 只改屏幕 2 的 y，保留它的 x |
| `EYE 2 POS` | `POS 2 <targetX> <targetY> <drawnX> <drawnY>` | 查询指定眼睛的目标与已绘制位置 |
| `XY 30 -20` | `OKXY 30 -20` | 双眼设置相同两轴目标，兼容旧客户端 |
| `POS` | `POS <targetX> <targetY> <drawnX> <drawnY>` | 兼容查询，只返回屏幕 1 |
| `INFO` | `INFO 240 320 -206 206` | 兼容旧单轴客户端 |
| `Y -60` | `OK -60` | 双眼修改 y，保留各自 x |
| `STATUS` | `STATUS alia-eye-wifi-10 <MAC> <display> <targetY> <drawnY>` | 版本、身份、显示开关及屏幕 1 的 y 位置 |
| `SYNC` | `OKSYNC` | v9 起：等待本轮绘制和 SPI 发送完成，再处理同一连接的后续指令；不是垂直同步，也不保证眼动已到达目标 |
| `EYE 1 FRAME` | `FRAME 1 <microseconds> <pixels> <frame_number>` | 最近一次本屏更新的绘制加 SPI 耗时、像素数、递增编号；v8 没有编号；不代表光学扫描完成 |
| `EYE 1 CAL` | `CAL 1 <cx> <cy> <angle10> <flipped> <reserved> <unsaved>` | 查询本屏校准；角度单位 0.1°，flipped/unsaved 为 0/1，reserved 固定为 0 |
| `EYE 1 CAL 120 160 35 0 0` | `OKCAL 1` | 设置中心、顺时针 3.5°、排针端朝上、末位保留 0，仅应用不落盘 |
| `EYE 2 RESETCAL` | `OKCAL 2` | 恢复本屏默认，仅应用 |
| `EYE 1 BL` | `BL 1 <percent> <duty>` | v10 起：查询本屏 0–100% 背光和 0–1024 的 LEDC 占空计数；诊断构建无 TFT 时返回软件计数 |
| `EYE 2 BL 25` | `OKBL 2 25` | v10 起：实时调整本屏背光为 25%，不重画、不改变几何、不自动保存 |
| `SAVECAL` | `OKSAVE` | 保存两屏已应用校准与背光；重复保存未变化值不重写 NVS |
| `LINK` | `LINK <uptime_ms> <status> <ap_error> <rssi> <channel> <bssid> <ps_error> <power_save> <free_heap> <min_heap>` | 只读无线状态，不改变眼睛位置或网络配置 |
| 非法或过长输入 | `ERR command` / `ERR line` | 拒绝输入，不改目标 |

`OK`/`OKXY` 表示目标已接受；用每眼的 `POS` 核对是否已绘制到目标。`display` 是固件是否启用显示的标志，不表示物理屏幕已应答；两块屏幕都没有接 MISO。`EYE` 仅接受编号 1/2 和 XY/Y/POS/CAL/RESETCAL/FRAME/BL 子命令；无效编号、越界整数及附加内容不改变任一目标。选择随每条命令传递，不跨客户端残留。

Y、XY、POS 及认证回复分别用一次写入发送完整行，减少小包数量；TCP 仍是字节流，客户端继续支持分片。串口客户端也会保留单次读取超时返回的半行，收到换行后再解析，回复上限为 128 字节、总等待仍为 5 秒；不会因半行或超时重发运动。`LINK` 中 `status=3` 表示 Wi-Fi 已连接；只有 `ap_error=0` 时 RSSI（dBm）、信道和 BSSID 有效，只有 `ps_error=0` 时实际省电值有效（0 为关闭）。堆内存单位为字节。串口额外记录 `WIFI_EVENT <uptime_ms> UP` / `DOWN <reason>`，联网后打印一次 LINK；不记录密码或令牌。

Python 接口：`connect_eyes()` 检查双屏能力，`connect_2d()` 获取范围，`set_xy(x, y, screen=1)` / `set_y(y, screen=2)` 控制单眼；省略 `screen` 同步控制双眼。旧 `connect()` 保留兼容。

未认证连接 3 秒关闭，已认证但空闲 12 秒关闭。手动模式每 5 秒保活。断线后设备保持最近目标并尝试重连，客户端报错退出，不重发结果未知的指令；断网时无法保证退出居中。协议有令牌认证，无 TLS，用于受信任的私人局域网。
